### 2.1 研究对象与符号（`B`）

- 数据集 Weather：2020 年全年、10 min 采样、21 个变量；**每个变量的完整序列视为一个 Token（channel token）**。
- 时序侧表示 \(H=\{h_1,\dots,h_{21}\}\)，文本侧语义表示 \(Z=\{z_1,\dots,z_{21}\}\)。
- **重要边界**：以上符号是机制图中的**概念抽象**；任务书明确说明「不代表已经确认原始代码中具体的张量结构和计算方式」。本报告全文沿用这一边界，不把 \(h_i\)/\(z_i\) 当作已实现张量。

### 2.2 模块 (a)：文本语义空间中的知识（`B`）

- 大语言模型语义空间中给出 5 个示例节点：气温、位温、露点温度、气压、风速。
- 气温 / 位温 / 露点温度之间存在**语义邻近关系**（虚线椭圆与虚线连接）。
- 强调「语义相关 / 物理相关」，并明确指出「**语义相关 ≠ 时序统计相关**」。
- 机制意图：利用 LLM 语义空间中的知识获得通道之间的语义邻近性。
- **未给出**：语义空间的构造方式、embedding 来源、相似度定义、归一化、阈值 / Top-k、是否显式引入物理知识（全部 `D`）。

### 2.3 模块 (b)：跨模态检索与对齐（`B`）

- 左侧时序通道 Token \(H=\{h_1,\dots,h_5\}\)，右侧文本语义 Token \(Z=\{z_1,\dots,z_5\}\)（**5 个示例节点，非 21 通道全量示意**）。
- **检索①**：由气温时序 Token \(h_1\) 发起，指向气温文本 \(z_1\)、位温文本 \(z_2\)、露点温度文本 \(z_3\)，即「**对应通道文本 + 邻近语义文本**」。
- **检索②**：由相关文本信息反向检索相关时序通道，得到 \(z_2\) 对应的位温时序 Token \(h_2\)、\(z_3\) 对应的露点温度时序 Token \(h_3\)，即「**相关通道时序信息**」。
- 图中公式：\(a_{ij}\propto \operatorname{sim}(h_i,h_j)+\beta\operatorname{sim}(z_i,z_j)\)，下方标注「数据证据（动态相似）+ 语义先验（语义相似）」；模块标注「跨模态对齐 / 检索式交互」。
- **严格边界**：公式、检索箭头、交互模块共同构成**机制示意**；未经代码或论文正文核实，**不得**解释为完整算法定义，也**不得**认定「检索 = 计算两个相似度矩阵」。

### 2.4 模块 (c)：语义增强的通道交互结果（`B`）

- 形成增强后的通道关系图与关系矩阵 \(A(H,Z)\)。
- 示意图中：气温 / 位温 / 露点温度之间连接较强，与气压之间中等，风速与其他变量之间较弱。
- 强调「文本语义先验改变通道表示几何结构 → 提升潜在依赖的可识别性」。
- **严格边界**：这是**机制示意结果，不是 Weather 真实数据计算得到的结果**；不得把示意边权强度当作实验结论，也不得预设语义增强一定改善结果。
